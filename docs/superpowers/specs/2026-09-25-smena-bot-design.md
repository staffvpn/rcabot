# СменаБот — Telegram-бот учёта кассовых смен

Дата: 2026-09-25
Статус: approved by заказчик (в переписке), спека фиксирует принятые решения

## 1. Назначение

Telegram-бот для одного заведения (кофейня/кондитерская, касса Quick Resto, Windows-терминал), который:
- ведёт сотрудника через открытие/закрытие смены с контролем чек-листа и сумм;
- напоминает о контрольном X-отчёте и опозданиях;
- служит базой инструкций по кассе (в том числе из базы знаний Quick Resto);
- полностью редактируется заказчиком самостоятельно через `/admin`-меню в этом же боте — без сайта, без участия разработчика после сдачи.

## 2. Масштаб

- Одно заведение, одна касса/терминал. Мультиточечность не проектируем (YAGNI) — при необходимости расширения потребуется отдельная спека.
- Один администратор на старте (владелец/управляющий), с возможностью добавлять/удалять других администраторов самостоятельно.
- Список сотрудников заказчик предоставит отдельно; интерфейс уже рассчитан на то, что их можно добавлять/удалять через `/admin` без разработчика.
- POS — Quick Resto (Windows-терминал). Интеграции с API Quick Resto нет: все кассовые действия (открытие/закрытие смены, X-отчёт, возвраты) сотрудник выполняет вручную на терминале, бот только фиксирует цифры и время параллельно и хранит инструкции.

## 3. Роли

- **Сотрудник** — открывает/закрывает смену, отвечает на X-отчёт, читает инструкции и справочные списки. Идентифицируется по своему Telegram-аккаунту (привязка ведётся в `/admin → Сотрудники`).
- **Администратор** — получает все уведомления (открытие/закрытие смены, расхождения, опоздания, X-отчёты) и редактирует весь контент бота через `/admin`. Админов может быть несколько, управляются они сами в разделе `/admin → Администраторы`.

## 4. Архитектура

- **Backend:** Supabase Edge Functions (Deno/TypeScript), бот работает через Telegram webhook — без отдельного сервера, без затрат на хостинг 24/7.
- **База данных:** Supabase Postgres.
- **Файлы:** Supabase Storage — фото Z-отчётов, видео-инструкции.
- **Планировщик:** `pg_cron` дёргает Edge Function по расписанию — напоминания за 10 минут до открытия/закрытия, контрольный X-отчёт в 14:20, проверка опозданий.
- Стек согласован с остальными проектами заказчика (тот же паттерн, что в BIGUNDER FM / Грядка) — бесплатный тариф, минимум обслуживания.

## 5. Модель данных (Postgres)

- `employees` — telegram_id, ФИО, активен/неактивен.
- `admins` — telegram_id, ФИО. Нельзя удалить последнюю оставшуюся запись.
- `schedule` — расписание по дням недели: пн–пт 08:30–19:30, сб 09:00–19:00, вс 09:00–18:00. Редактируется в `/admin`.
- `shifts` — одна запись на смену сотрудника за день: время открытия/закрытия, статус прохождения чек-листа, сумма размена при открытии, суммы X-отчёта (нал/безнал), фото Z-отчёта при закрытии, флаг расхождения размена.
- `checklist_items` — пункты чек-листов открытия и закрытия: фаза (`open`/`close`), тип (`checkbox` — обычная отметка, `photo` — требует прикреплённого фото), текст, порядок. Дефолт open: «Кофемашина прогрета», «Терминал включён», «Зал чистый». Дефолт close: «Фото отчёта с кассы» (тип `photo`). Оба списка полностью редактируются в `/admin` — можно добавлять/удалять/переставлять пункты в любой фазе, включая сам пункт с фото.
- `instructions` — статьи раздела «Инструкции»: заголовок, текст, опционально файл/видео (Supabase Storage) или ссылка. Стартовый набор — п. 7.
- `expiry_items` — сроки годности десертов: название, количество суток. Стартовый набор — п. 7.

История X-отчётов отдельно не хранится как фича с UI — сырые цифры лежат в `shifts`, но выделенного экрана просмотра истории нет (заказчик подтвердил, что не нужно).

## 6. Сценарии

### 6.1 Персональная панель сотрудника
Постоянная клавиатура внизу чата (не набор команд):
- 🟢 OPEN / 🔴 CLOSER (кнопка меняется в зависимости от состояния смены);
- 🧾 Контрольный X-отчёт;
- 📖 Инструкции;
- 🍰 Сроки годности.

### 6.2 Открытие смены
1. Сотрудник жмёт **OPEN**.
2. Бот показывает пункты чек-листа кнопками; смена не считается открытой, пока не отмечены все пункты.
3. Бот запрашивает сумму наличных в кассе (размен).
4. Сумма сравнивается с суммой закрытия предыдущей смены (введена сотрудником при предыдущем CLOSER). При расхождении — предупреждение сотруднику и уведомление админу; **открытие не блокируется** (буквально по ТЗ: «выдать предупреждение»).
5. Админ получает уведомление о факте и времени открытия.

### 6.3 Опоздания
- За 10 минут до времени открытия по расписанию — напоминание сотруднику.
- Если к моменту открытия по расписанию OPEN не нажат — уведомление админу об опоздании.

### 6.4 Контрольный X-отчёт
- В 14:20, только в рабочие по графику дни, бот сам присылает напоминание с кнопкой.
- Сотрудник вводит сумму наличных и безналичных.
- Цифры уходят подтверждением сотруднику и уведомлением админу. Отдельного архива/истории отчётов не строим.

### 6.5 Закрытие смены
- За 10 минут до времени закрытия по расписанию — напоминание.
- Сотрудник жмёт **CLOSER** → бот показывает чек-лист закрытия (тот же механизм, что и при открытии, п. 6.2): обычные пункты-галочки плюс минимум один пункт типа «фото» (по умолчанию — «Фото отчёта с кассы»). Смена закрывается, только когда все пункты выполнены и все обязательные фото прикреплены.
- Список пунктов закрытия полностью редактируется в `/admin` — можно добавить свои условия (например, «Выключить кофемашину», «Сдать ключи») или изменить требование по фото.
- Бот подтверждает закрытие сотруднику и пересылает все данные чек-листа (включая фото) + время закрытия админу.

### 6.6 Инструкции
Один раздел с подменю (не разбросанные кнопки), источник текстов — ТЗ заказчика и база знаний Quick Resto (quickresto.ru/support, раздел Windows-терминала), отфильтрованная до того, что нужно кассиру:
1. Возврат чека (наличные) — включая предупреждение, что после закрытия смены возврат через терминал невозможен.
2. Возврат безналичной оплаты — 2 способа (до и после сверки итогов).
3. Аварийная отмена оплаты картой.
4. Как напечатать X-отчёт (кассовый).
5. Печать / отмена пречека.
6. Где искать чеки повара и пречеки.
7. Информация по смене (фискальные счётчики / нефискальные оплаты).
8. Списания — причины и порядок (текст + ссылка от заказчика, когда пришлёт).

Каждый пункт — текст, опционально с прикреплённым видео или ссылкой. Список расширяем через `/admin` без релиза кода.

### 6.7 Сроки годности
Статичный список (название десерта — количество суток), редактируется в `/admin`. Стартовые данные:
Канеле — 2 суток, Пирог миндаль — 5 суток, Чизкейк — 3 суток, Пирог смородина — 5 суток, Пирог вишня — 5 суток, Тарт лимонный — 3 суток, Кексы — 5 суток, Наполеон — 5 суток, Медовик — 5 суток, Картошка — 5 суток.

### 6.8 Админ-панель (`/admin`)
Шесть разделов, единый паттерн редактирования (текст/фото → добавить, 🗑 → удалить):
- ✏️ Чек-лист открытия
- ✅ Чек-лист закрытия — тот же интерфейс, что у открытия; можно добавлять свои пункты и менять/удалять пункт с фото.
- 📖 Инструкции
- 🧑‍🍳 Сотрудники
- 🍰 Сроки годности
- 🛡️ Администраторы — добавление нового админа через пересланное от него сообщение (бот берёт telegram_id оттуда, вручную ID вводить не нужно); удаление кнопкой 🗑. Система не даёт удалить последнего оставшегося админа.

## 7. Открытые вопросы (не блокируют разработку)

- Список сотрудников (ФИО + Telegram) — пришлёт заказчик, вносится через `/admin → Сотрудники`.
- Название заведения — пришлёт заказчик, используется в приветственных сообщениях.
- Ссылка/материалы по списаниям — пришлёт заказчик, добавляется в `instructions` как есть.

## 8. Вне рамок (не делаем)

- Интеграция с API Quick Resto.
- Мультиточечность/мультиарендность.
- Отдельный экран истории X-отчётов.
- Веб-админка — вся админ-функциональность живёт в самом Telegram-боте.

## 9. Тестирование

- Ручная проверка сценариев 6.2–6.6 в тестовом Telegram-чате (сотрудник + админ) перед сдачей.
- Проверка граничных случаев: чек-лист не пройден до конца, расхождение размена, опоздание, попытка удалить последнего админа.
